# Army System — Unity Tactical Battle Simulator

## Project Overview

This is a **2D real-time tactical battle simulation** built in Unity (URP). Players command armies of formation-based units in real-time combat against AI opponents. The project features:

- **Formation-based unit movement** — Units consist of multiple models arranged in formations, with steering-behavior composition for smooth navigation
- **Influence-map-driven AI** — Positions are generated by an `IGenerator`, scored by pluggable `IEvaluate` evaluators, and the highest-scoring position is selected for movement
- **Capture point system** — Fortresses, villages, banners, and misc points contested by moving models into trigger zones
- **Campaign meta-game** — Persistent progression with money, prestige, character management, and pre-battle buy/sell screens
- **GPU-accelerated collision maps** — Compute shaders generate real-time occupancy/collision heatmaps for AI pathfinding visualization

## Architecture

### Core Systems

| System | Location | Description |
|--------|----------|-------------|
| Battle Controller | `Battle Scripts/Controller/Battle.cs` | Singleton orchestrating battles; manages deployment, win/loss conditions |
| Army Container | `Battle Scripts/Controller/Army.cs` | Holds lists of `IUnit` children; determines enemy relationships via transform hierarchy |
| Capture Point | `Battle Scripts/Controller/CapturePoint.cs` | Contestable positions with holder float (-1 to 1) and capture threshold |
| Unit Base | `Battle Scripts/Unit/IUnit.cs` | Abstract unit contract: stats, state, melee tracking, raycasting |
| Unit Impl | `Battle Scripts/Unit/Unit.cs` | Concrete unit implementation with model-level melee engagement |
| Stats System | `Battle Scripts/Unit/Stats/` | ScriptableObject-based stat blocks (`IUnitStatBlock`, `PC_Stats`, `NPC_Stats`) |
| Movement | `Battle Scripts/Unit/Unit movement/` | Reynolds-style steering behaviors composed by priority (GoTo, MeleeEnemy, FleeFromNearestEnemy, etc.) |
| AI Core | `Battle Scripts/AI/AI architectures/` | Influence map (`InfluenceMap.cs`), unit behavior base (`UnitBehaviour.cs`), blackboard perception storage |
| Squad AI | `Battle Scripts/AI/SquadAI/` | Squad-level ordering: position evaluators, circle generator, order management |
| Unit AI | `Battle Scripts/AI/UnitAI/` | Individual unit queries and behavior trees |
| Pathfinding | `Battle Scripts/Pathfinding/` | NavMesh 2D-based pathfinding via `IPathfinder` interface |
| Player Input | `Battle Scripts/Player IO/` | Unity Input System (.inputactions): camera, selection, ordering, cursor |

## Architecture Patterns

1. **Singleton Pattern** — `Battle.Instance`, `CampaignDataManager.instance`, `CollisionMapManager.instance` for global access
2. **Interface-Based Design** — Heavy use of abstract contracts (`IUnit`, `ISquad`, `IEvaluate`, `IQuery`, `IPossibleMoves`, `IPathfinder`) enabling pluggable components
3. **Influence Map AI** — Generate positions → score with evaluators → select best move. Perception stored in a blackboard dictionary
4. **Steering Behavior Composition** — Individual behaviors produce forces, aggregated by priority into final movement vector
5. **Event-Driven Communication** — C# events and `UnityEvent` for decoupled state changes, unit destruction, capture events
6. **Data-Oriented Stats** — ScriptableObject stat blocks with separate NPC/PC implementations for balance tuning
7. **JSON Persistence** — Campaign data serialized to JSON in `Application.persistentDataPath`
8. **GPU Collision Maps** — Compute shaders generate real-time occupancy maps rendered as visual sprites

## Scene Flow

- **Scene 0**: Main menu (new game, load game)
- **Scene 1**: Campaign / battle preparation (buy/sell units, deploy)
- **Scene 2**: Battle victory screen

`Battle.cs` loads scene 2 on win, scene 0 on loss (destroying `CampaignDataManager` on defeat).

## Building and Running

This is a Unity project — open it in the Unity Editor to build and run. No CLI build scripts or npm tooling present. Standard Unity workflow applies:

1. Open project in Unity Editor
2. Ensure URP is configured (`URP.asset`, `URP_Renderer.asset` present)
3. Use Unity's Input System package (`.inputactions` file at `Battle Scripts/Player IO/PlayerInputMap.inputactions`)
4. Build via **File → Build Settings** or **File → Build And Run**

## Development Notes

- **Formation-based combat**: Units contain multiple "models" within formations. Melee tracking and combat operate at model level but report to unit level
- **AI evaluation colors** (Gizmos): white = default, red = flanking, green = movement, blue = shooting
- **Unit states**: `Deployment`, `Idle`, `Moving`, `Fighting`, `Fleeing`
- **Capture point types**: Fortress, Village, Banner, Misc — threshold-based ownership (default 0.8)
- **Collision map resolution**: Configurable grid with default 8 pixels per unit
- **Project root `.gitignore`**: Standard Unity template (ignores Library/, Temp/, Obj/, Build/, .csproj, .sln)
